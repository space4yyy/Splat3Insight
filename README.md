# Splat3 Insight

跨平台桌面应用：Splatoon 3 的 SplatNet 数据面板，附带透明的 OBS 数据卡片。

## 功能

- 数据面板：涵盖总览、对战、武器、场地、鲑鱼跑和对战记录，支持按时间范围与模式筛选，并可在对战记录中查看每场对局详情。
- OBS 数据卡片：提供自动、蛮颓比赛、X 比赛、鲑鱼跑四种对战/打工卡片，以及单行展示巨大鲑鱼与头目鲑鱼累计击倒数量的击倒数量卡片、显示本机时间的时钟卡片，背景透明度可调。
- 添加并管理多个 Nintendo Account。
- 从 SplatNet 3 同步历史对战与打工记录，并在后台增量更新：OBS 服务开启时每 15 秒同步一次，其余时间每 5 分钟同步一次；窗口切回前台或点击“立即同步”时立即触发同步。
- 战力变化仅与同一赛道的记录比较：X 比赛按规则，蛮颓比赛（挑战）按武器，蛮颓比赛（开放）按模式，活动比赛按活动。开放与活动比赛重新测定战力后，首场从 +0 开始计算。
- 完整保留原始对战数据；SQLite 中的原始 JSON 经过 gzip 压缩并按记录去重。
- 登录凭据安全存储在操作系统凭据库中（macOS 钥匙串、Windows 凭据管理器）。

## 下载与安装

在 [Releases](https://github.com/space4yyy/Splat3Insight/releases/latest) 下载最新版本。

### macOS

下载并双击打开 `.dmg`，将 **Splat3 Insight** 拖入「应用程序」。

如果提示「已损坏，无法打开」或「无法验证开发者」，请使用以下方法：

**方法一：通过终端清除隔离扩展属性**

打开「终端」，输入 `xattr -dr com.apple.quarantine`，在末尾添加一个空格，然后将无法打开的文件拖进终端，按回车执行。

- 如果 `.dmg` 无法打开，拖入下载的 `.dmg` 文件。
- 如果 App 无法启动，拖入「应用程序」中的 `Splat3 Insight.app`。

执行完成后，再次打开文件或应用。

**方法二：通过系统设置允许打开**

尝试打开应用后，进入「系统设置 → 隐私与安全性」。如果出现「仍要打开」按钮，点击后按提示确认。

### Windows

下载 `-setup.exe` 并运行。若出现「Windows 已保护你的电脑」提示，点击「更多信息 → 仍要运行」。

### 更新

后续有新版本时会在「设置 → 通用」中提示，点击「更新到 x.y.z」即可下载安装并重启。应用不会自动安装更新，以免在直播期间中断 OBS 卡片。

## 开发环境

- Rust stable 与 Cargo
- Node.js 和 npm
- Tauri 2 所需的操作系统开发组件

安装桌面端依赖：

```sh
npm --prefix desktop install
```

启动桌面开发版：

```sh
make dev
```

也可以直接运行：

```sh
npm --prefix desktop run tauri -- dev
```

在 macOS 上可先运行一次 `make dev-signing`：开发版将使用本机固定证书签名，钥匙串的“始终允许”授权在重新编译后依然有效，无需重复输入密码。

## 构建与检查

```sh
make test       # 运行 Rust 与前端测试
make fmt-check  # 检查 Rust 格式
make check      # 检查 Rust crates
make build      # 构建桌面安装包
```

每次推送后，GitHub Actions 会构建 Windows 安装包（`.github/workflows/build-windows.yml`）。

## 发布

1. 首次发布前运行 `make release-signing`，生成自动更新签名密钥与 macOS 发布证书，按提示将内容配置到仓库的 Actions secrets 中，并妥善备份生成的目录。若丢失更新私钥，已安装的旧版本将无法接收后续更新。
2. 在 `CHANGELOG.md` 顶部补充当前版本的更新说明：使用 `## 0.3.0（日期）` 作为标题，下方按「新增 / 改进 / 修复」分组。
3. 在 `main` 分支运行 `make release VERSION=0.3.0`：脚本会校验 `CHANGELOG.md` 中是否包含该版本说明，更新版本号并连同 `CHANGELOG.md` 一并提交，最后创建 `v0.3.0` 标签（不会自动推送）。其他代码改动需在执行前先行提交。
4. 推送 `main` 分支与标签：`git push origin main v0.3.0`。GitHub Actions（`.github/workflows/release.yml`）会构建 macOS 与 Windows 安装包，并上传至同名 Release 草稿。草稿正文由 `CHANGELOG.md` 对应章节与安装说明组成。
5. 下载草稿中的安装包验证无误后，在 GitHub 页面正式发布该 Release。发布后，已安装的应用即可通过该 Release 中的 `latest.json` 接收更新。

macOS 发布流程会将 Secrets 中的证书导入构建机的临时钥匙串，验证签名后打包，并在构建结束时自动清理。项目生成的自签名证书可直接使用，无需更换证书或更新密钥。修改发布流程后，需使用包含该改动的新版本标签触发构建；重新运行旧标签任务仍会使用旧版本代码。

## OBS 设置

1. 应用启动后会自动运行 OBS 服务，也可在“其他工具”页面停止或重新启动。
2. 在“其他工具”页面选择卡片类型并复制 OBS 地址（例如自动卡片地址为 `http://127.0.0.1:17353/overlay`）。
3. 在 OBS 中添加“浏览器”来源并填入该地址：对战/打工卡片宽高设为 **1280 × 320**（或其他 4:1 尺寸）；时钟卡片地址为 `http://127.0.0.1:17353/clock`，宽高设为 **640 × 240**（或其他 8:3 尺寸）；击倒数量卡片地址为 `http://127.0.0.1:17353/defeat-counts`，宽高设为 **3072 × 256**（或其他 12:1 尺寸）。
4. 如需显示卡片背景，可在调整透明度后，将页面提供的 CSS 粘贴至 OBS 浏览器来源属性的“自定义 CSS”中。

卡片按浏览器来源的宽高等比缩放，并按来源分辨率渲染：在画面中缩小可保持清晰，放大超过来源尺寸则会略微模糊。

若端口 17353 已被占用，应用会显示服务错误状态；关闭占用端口的程序后重新启动服务即可。

## 数据与隐私

登录 SplatNet 3 需借助第三方服务 [nxapi](https://github.com/samuelthomas2774/nxapi-znca-api) 生成登录参数：在登录和刷新令牌时，Nintendo 账号的 `id_token`、Nintendo Switch Online 应用接口（Coral）令牌及与 Coral 交互的数据会发送至 nxapi。每次添加账号前，应用均会展示此说明，经确认后才会开始登录流程。

账号元数据与压缩后的对战/打工历史保存在操作系统为应用分配的数据目录中。Nintendo 与 SplatNet 凭据存储在系统凭据库中，不会写入代码仓库；应用日志不会记录密码、登录回调链接及令牌内容。

可在“设置”的账号列表中导出各账号的历史数据，导出文件默认保存在“下载”文件夹，也可在“设置 → 通用 → 数据导出位置”中更改保存路径。导出文件支持在其他设备上重新导入，本地已有的记录不会重复写入。删除账号时默认仅移除登录凭据并保留本地历史记录；若勾选“同时删除本地数据”，则会一并清除本地历史记录（已导出的备份文件不会受影响）。
